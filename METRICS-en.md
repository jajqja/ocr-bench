# OCR Evaluation Metrics Specification

This document defines and explains the evaluation metrics used across both stages of our End-to-End OCR pipeline: **Textline Detection** and **Text Recognition**.

---

## 1. Text Recognition Metrics

This stage evaluates the linguistic accuracy of the decoded text generated by the model (Predicted Text) against the ground truth labels (Ground Truth Text) using the **Levenshtein Distance (Edit Distance)** algorithm at both character and word levels.

### 1.1. Character Error Rate (CER)
CER measures the percentage of incorrectly predicted characters relative to the total number of characters in the ground truth.

* **Formula:**
    $$CER = \frac{S + D + I}{N_c}$$
    * $S$ (Substitutions): The number of characters incorrectly replaced (e.g., `u` instead of `v`).
    * $D$ (Deletions): The number of characters missed by the model.
    * $I$ (Insertions): The number of extra characters falsely added by the model.
    * $N_c$: The total number of characters in the Ground Truth.
* **Characteristics:** Lower is better ($0.0$ signifies a perfect match). CER is highly sensitive to diacritics and tone marks in Vietnamese administrative documents.

### 1.2. Word Error Rate (WER)
WER shares the same mathematical definition as CER but shifts the unit of evaluation from individual characters to **words** (strings separated by whitespace).

* **Formula:**
    $$WER = \frac{S_w + D_w + I_w}{N_w}$$
    * $S_w, D_w, I_w$: The number of word substitutions, deletions, and insertions respectively.
    * $N_w$: The total number of words in the Ground Truth.
* **Characteristics:** Lower is better. This is a strict metric; a word is counted as a total error even if only a single character within it is wrong.

### 1.3. Accuracy (Line-Level Sequence Accuracy)
This metric measures the percentage of textlines that the model recognizes **100% perfectly**, without a single character or spacing mismatch.

* **Formula:**
    $$\text{Accuracy} = \frac{\text{Number of Perfectly Matched Textlines}}{\text{Total Number of Evaluated Textlines}}$$
* **Characteristics:** This is the most stringent metric. If a textline contains 100 words and misses just a single period or capitalization, the entire line receives a score of $0$. This serves as an excellent benchmark for data extraction quality in critical administrative paperwork.

## 2. Textline Detection Metrics

Our system employs a custom **Area-based/Coverage-based Approach** powered by the `shapely` geometric library. This setup is specifically engineered to handle textline-specific issues like line-splitting (fragmentation) and box overlaps.

### 2.1. Coverage Calculation (`calculate_coverage`)
Instead of classic 1-to-1 IoU bounding box matching, the system calculates area overlap from two independent perspectives:

* **Precision Perspective:** Iterates through each predicted bounding box (`pred`) to measure what percentage of its area falls cleanly inside the actual text regions (`references`).
* **Recall Perspective:** Iterates through each ground truth box (`reference`) to measure what percentage of its area is successfully enveloped by the model's predictions (`preds`).

### 2.2. Penalization Mechanism (`penalize_double=True`)
To prevent the model from "gaming" the metrics by predicting multiple overlapping boxes over a single line (Double Detection) or fracturing a line into pieces, the following geometric penalty is applied:

$$\text{Overlap Area} = \text{Gross Intersection Area} - \text{Net Coverage Area (Union)}$$
$$\text{Final Area} = \max(0.0, \text{Net Coverage Area} - \text{Overlap Area})$$

Regions overlapping multiple times act as point deductions, tanking the score of redundant or poorly localized boxes.

### 2.3. Bounding Box Object-Level Precision & Recall
After computing the area coverage score for every individual box, the system applies a strict threshold filter — **$\text{Threshold} = 0.7$ (or $0.8$)** — to categorize each box as True ($1$) or False ($0$). This threshold guarantees that boxes cropping out vital character descenders, ascenders, or tone marks are rejected.

* **Precision:**
    $$\text{Precision} = \frac{\text{Number of Predicted Bboxes exceeding Threshold (> Threshold)}}{\text{Total Number of Predicted Bboxes}}$$
* **Recall:**
    $$\text{Recall} = \frac{\text{Number of Ground Truth Textlines exceeding Threshold (> Threshold)}}{\text{Total Number of Actual Textlines}}$$

## 3. Global Unified Penalized IoU Matrix

For overall benchmarking reports requiring a single representative geometric score (`match_boxes`), the system applies a differentiated penalty strategy based on the severity of the detection error within the OCR ecosystem:

| Geometric Case State | Assigned IoU Score | Severity Level | Practical Impact on System |
| :--- | :---: | :---: | :--- |
| **Valid Geometric Match** | From $0.7 \rightarrow 1.0$ | No Penalty | The bounding box tightly encapsulates the textline with clean margins. |
| **False Positive / Noise** (`unassigned_pred`) | **$0.0$** | Low Penalty | The model detects text on blank backgrounds. The Recognition stage will crop this into empty strings or minor noise $\rightarrow$ easily filtered out. |
| **Missed Textline / False Negative** (`unassigned_actual`) | **$-1.0$** | Critical Penalty | The model completely skips a line of text. The text is permanently lost to the pipeline $\rightarrow$ Heavily punishes the global score to sound an alarm. |
