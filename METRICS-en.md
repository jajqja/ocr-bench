# OCR Evaluation Metrics System

This document specifies and details the calculation methods for the evaluation metrics utilized across both stages of the OCR pipeline: **Textline Detection** and **Text Recognition**.

---

## 1. Text Recognition Metrics

This stage evaluates the linguistic and decoding accuracy of the predicted text generated by the model against the ground truth text. These metrics are computed using the **Levenshtein Distance (Edit Distance)** algorithm at both character and word levels.

### 1.1. Character Error Rate (CER)
CER measures the percentage of incorrectly predicted characters relative to the total number of characters in the ground truth.

* **Formula:**
    $$CER = \frac{S + D + I}{N_c}$$
    * $S$ (Substitutions): The number of incorrectly replaced characters (e.g., `u` instead of `v`).
    * $D$ (Deletions): The number of characters omitted by the model.
    * $I$ (Insertions): The number of extra characters falsely added by the model.
    * $N_c$: The total character count in the ground truth text.
* **Characteristics:** Lower values indicate superior performance ($0.0$ represents a flawless prediction). CER is highly effective at reflecting the model's capability to recognize Vietnamese diacritics, which are prone to misinterpretation or omission.

### 1.2. Word Error Rate (WER)
WER shares the same underlying logic as CER, but the unit of evaluation shifts from individual characters to **word-level tokens** (character sequences delimited by whitespaces).

* **Formula:**
    $$WER = \frac{S_w + D_w + I_w}{N_w}$$
    * $S_w, D_w, I_w$: The number of substituted, deleted, or inserted words, respectively.
    * $N_w$: The total word count in the ground truth text.
* **Characteristics:** Lower values indicate better performance. Since it operates at the token level, a word is flagged as erroneous if even a single character within it is mispredicted.

### 1.3. Line-Level Accuracy
This metric measures the exact percentage of textlines decoded by the model with **100% absolute precision**, tolerating zero discrepancies compared to the ground truth.

* **Formula:**
    $$\text{Accuracy} = \frac{\text{Number of Perfect Line Matches}}{\text{Total Number of Evaluated Textlines}}$$
* **Characteristics:** This is the most stringent metric among the three. If a line consists of 100 words, a single incorrect punctuation mark or casing mismatch will disqualify the entire textline, resulting in a score of $0$ for that specific sample. This metric is crucial when evaluating the formatting requirements of administrative and official documents.

## 2. Textline Detection Metrics

### 2.1. Object-Level Precision & Recall
This evaluation framework implements a custom **Area-Based Coverage Approach** powered by the `shapely` geometric analysis library to inherently manage line fragmentation and bounding box overlap anomalies.

#### Coverage Computation Methodology

* **Precision-Centric Coverage:** Iterates through each predicted bounding box (`pred`) to calculate the ratio of its area that effectively intersects with the ground truth boxes (`references`).
* **Recall-Centric Coverage:** Iterates through each ground truth bounding box (`reference`) to calculate the ratio of its area that is successfully captured by the collective union of predicted bounding boxes (`preds`).

#### Precision & Recall Classification
Following the coverage scoring for each discrete bounding box, a strict acceptance **$\text{Threshold} = 0.5$** is applied to classify the prediction as either correct ($1$) or incorrect ($0$). This threshold guarantees that predictions clipping text bounds or losing character accents are penalized.

* **Precision:**
    $$\text{Precision} = \frac{\text{Number of Predicted Bboxes Meeting Coverage Threshold (> Threshold)}}{\text{Total Number of Bboxes Rendered by the Model}}$$
* **Recall:**
    $$\text{Recall} = \frac{\text{Number of Ground Truth Textlines Meeting Coverage Threshold (> Threshold)}}{\text{Total Number of Ground Truth Textlines}}$$
* **F1-Score:**
    $$\text{F1-Score} = 2 \times \frac{\text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}}$$
    *The **F1-Score** is the harmonic mean of Precision and Recall. It functions as the definitive singular metric to objectively assess the localization capabilities of the detection model, ensuring the system is balanced against over-detection (**Low Precision**) and under-detection (**Low Recall**).*

### 2.2. Page-Level Intersection over Union (Page-IoU)

This geometric metric gauges the absolute layout accuracy, alignment, and structural cohesion of the global predicted bounding box network (`preds`) against the ground truth coordinates (`references`) across the entire document plane.

#### Topological Conventions
Rather than evaluating IoU over explicit $1\text{-to-}1$ box assignments (which are highly susceptible to false scores from line-splitting or stacking errors), this method uses `shapely` to perform a flattened topological analysis:
1. Merges all fragmented predicted bounding boxes into a singular flattened polygon footprint ($\mathcal{P}_{\text{union}}$).
2. Merges all fragmented ground truth bounding boxes into a singular flattened polygon footprint ($\mathcal{G}_{\text{union}}$).

#### Mathematical Formulation

The **Page-Level IoU** is calculated as the ratio of the intersection area to the union area of these two holistic topological planes:

$$IoU_{\text{page}} = \frac{\text{Area}(\mathcal{P}_{\text{union}} \cap \mathcal{G}_{\text{union}})}{\text{Area}(\mathcal{P}_{\text{union}} \cup \mathcal{G}_{\text{union}})}$$

Where:

$$\text{Area}(\mathcal{P}_{\text{union}} \cup \mathcal{G}_{\text{union}}) = \text{Area}(\mathcal{P}_{\text{union}}) + \text{Area}(\mathcal{G}_{\text{union}}) - \text{Area}(\mathcal{P}_{\text{union}} \cap \mathcal{G}_{\text{union}})$$

*Definitions:*
* $\mathcal{P}_{\text{union}} = \bigcup_{p \in \text{preds}} p$: The flattened union polygon derived from all predicted boxes.
* $\mathcal{G}_{\text{union}} = \bigcup_{g \in \text{references}} g$: The flattened union polygon derived from all ground truth boxes.
* $\cap$: The geometric intersection operation.
* $\cup$: The geometric union operation.

#### Corner Cases
The framework enforces rigorous boundary rules for blank documents or edge-case predictions:
* **$IoU_{\text{page}} = 1.0$**: Triggered when a document page is entirely blank (contains no text annotations) and the model accurately refrains from rendering any predictions ($\text{len}(\text{gts}) = 0 \text{ and } \text{len}(\text{preds}) = 0$).
* **$IoU_{\text{page}} = 0.0$**: Triggered when either the prediction pool or the ground truth pool is entirely empty while the opposing set contains valid polygons (e.g., text is present but the model completely fails, or the page is blank but the model generates hallucinations).
* **Acceptance Criterion**: Inherited from standard Object Detection conventions, an individual localized box prediction is mathematically accepted as a True Positive (TP) provided that its **$IoU \ge 0.5$**.
